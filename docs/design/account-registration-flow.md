# 小雾账号注册体验

## 状态

已于 2026-08-11 确认共同理解。本文是产品体验规格，不授权实现、部署或开放生产注册。

## 目标

让访客在需要加入书架、同步进度或跨设备继续时，由小雾通过手机全屏对话式引导建立待验证账号；访客完成邮箱确认后激活账号、自动建立会话，并安全地继续原注册意图。

生产环境现有账号注册代码已经存在，但 Turnstile public site key 当前为空。真实运营主体、联系邮箱、隐私政策、服务条款和账号信息请求渠道也尚未就绪，因此生产注册保持关闭。

## 体验原则

- 小雾是全平台稳定人格；故事终端是作者可配置的叙事频道。
- 游客仍可浏览和阅读公开内容，注册是价值触发的邀请而非登录墙。
- 拟人化来自表情、节奏和回应；邮箱、密码、安全验证等动作始终使用真实名称。
- 账号安全规则归 `AccountLifecycle`；React 只渲染状态、发送事件并回送结果。
- 手机端是唯一设计基准，桌面端维持居中的手机阅读视口。

## Cloudflare 资源与 adapter

本功能只声明实际使用的资源。`AccountLifecycle` 的外部 interface 不暴露 Cloudflare SDK、Drizzle、Resend 或浏览器存储细节；资源 seam 是 module implementation 的内部 seam，HTTP 和 React 调用方仍只表达账号领域意图。

| 资源 | 使用 | seam 与 adapter | 职责 |
|---|---|---|---|
| Worker | 是 | HTTP route 是 `AccountLifecycle` 的 HTTP adapter；Worker 入口只负责托管请求 | 动态页面、账号请求、cookie 和响应映射 |
| D1 | 是 | module 内部 `AccountStore` interface；生产 `DrizzleD1AccountStore` adapter；测试使用 in-memory adapter 或 D1 runtime adapter | 账号、session、token、注册同意、频控和待验证账号清理 |
| KV | 否 | 无 seam、无 binding | 当前没有读取频繁且允许最终一致性的注册配置或缓存 |
| R2 | 否 | 无 seam、无 binding | 注册不读写文件或对象；小雾静态资源随应用构建交付 |
| Durable Objects | 否 | 无 seam、无 binding | token 消费、凭据替换和账号激活通过 D1 条件写入与原子操作完成，不需要单点协调 |
| Queues | 首版否 | 无 seam、无 binding | 首版保持“邮件已经发送”这一同步结果语义，并通过有界超时、幂等键和显式恢复处理投递 |
| Cloudflare Turnstile | 是 | `TurnstileVerifier` interface；生产 Cloudflare adapter；测试 mock adapter | 人机验证与 action 校验 |
| Resend | 是 | `AuthMailer` interface；生产 Resend adapter；测试 mock adapter | 验证邮件和后续账号邮件投递 |
| Worker Observability | 是 | `RegistrationTelemetry` interface；生产结构化日志 adapter；测试 spy adapter | 记录不含个人内容的注册分析事件 |
| 浏览器 Web Storage | 是，非 Cloudflare 资源 | `RegistrationDraftStore` interface；生产 Web Storage adapter；测试 in-memory adapter | 当前设备的 24 小时无秘密注册草稿 |

Worker vars/secrets 只在 composition root 读取并组成 `AccountRegistrationConfig` 后注入 implementation。业务规则不得直接读取 `cloudflare:workers` env，也不得依赖 binding 名称。

`AccountStore` 是内部 persistence seam，不扩大 `AccountLifecycle` 的外部 interface。它必须隐藏 Drizzle 查询、D1 batch/条件写入和事务细节；生产 adapter 与测试 adapter 穿过同一内部 interface，测试仍以正式 `AccountLifecycle` interface 为主要行为表面。

## 入口

- 顶部提供清晰的“登录 / 注册”入口。
- 访客尝试加入书架、同步进度或跨设备继续时，小雾发出情境注册邀请。
- 访客关闭邀请后，本次会话不再主动出现；以后只在访客再次表达账号意图时邀请。
- 小雾菜单始终保留主动注册入口。

## 主流程

1. 小雾结合当前注册意图解释建立账号的价值，并允许“暂时不用”。
2. 在收集个人信息前展示简明告知；访客分别完成年龄确认和注册同意。
3. 小雾询问可重复、可修改且不用于登录的昵称。
4. 访客输入邮箱；界面说明邮箱用于验证与找回账号且不会公开。
5. 访客设置至少十五个字符的密码。允许空格、中文、粘贴、自动填充和密码管理器，不要求字符组合。
6. Managed Turnstile 在 `interaction-only` 模式运行；需要操作时明确显示“安全验证”。
7. 访客确认提交后创建待验证账号并发送二十四小时有效的验证邮件。
8. 邮件链接先打开确认页；访客点击“确认并进入幻界”后才消耗 token、激活账号并建立会话。
9. 同一设备自动完成安全的幂等注册意图或返回原界面等待确认；其他设备进入小雾欢迎页。
10. 账号激活后再单独询问是否同步阅读偏好，拒绝不影响账号使用。

## 注册草稿

当前设备临时保存注册意图、步骤、昵称和邮箱，不保存密码、安全验证 token 或注册同意。草稿在注册完成或二十四小时后清除；条款或隐私政策版本变化时必须重新确认。

## 恢复矩阵

| 状态 | 小雾的解释 | 可用动作 |
|---|---|---|
| 邮箱属于正常账号 | 明确说明已有账号 | 登录、找回密码 |
| 邮箱属于待验证账号 | 说明旅程尚未完成 | 保留凭据重发；或明确重新开始、原子更新昵称与密码、作废全部旧链接后发送新链接 |
| 邮件投递失败 | 不声称已经发送，说明待验证账号仍保留 | 重试发送、修改邮箱 |
| 链接过期 | 说明链接已失效，不要求重填完整表单 | 输入邮箱、完成安全验证后重发 |
| 链接无效 | 不透露账号状态 | 进入重新发送入口 |
| 链接已使用且已有会话 | 识别账号已激活 | 欢迎回来并继续 |
| 网络超时或结果不确定 | 先确认上一次操作结果 | 确认未成功后用同一幂等标识重试 |
| 达到发送频率限制 | 显示下次可操作时间 | 保留待验证状态，稍后重试 |

首次邮件发送后六十秒才可重发；同一邮箱与来源地址三十分钟最多五次。待验证账号从最后一次成功发送验证邮件起保留七天，逾期清除账号、未使用 token 和注册同意记录。

## 核心文案

| 状态 | 小雾主台词 | 主要操作 |
|---|---|---|
| 邀请 | “想让我替你记住这段旅程吗？建立账号后，书架和进度就不会留在这台设备里。” | 建立账号 / 暂时不用 |
| 说明 | “开始前，有几件重要的事要和你说清楚。” | 年龄确认、条款与隐私确认 |
| 昵称 | “我该怎么称呼你？以后随时可以修改。” | 输入昵称 |
| 邮箱 | “邮箱是你回到账号的路标，我也会把验证邮件送到这里。” | 输入邮箱 |
| 密码 | “给账号设一把只有你知道的钥匙。我不会朗读或保存输入内容。” | 输入密码 |
| 安全验证 | “最后确认一下是你本人在操作。” | 安全验证、提交 |
| 等待邮件 | “邮件已经出发。我会在这里等你回来。” | 查看邮箱、重发、修改邮箱 |
| 激活确认 | “邮箱确认好了。准备继续刚才的旅程吗？” | 确认并进入幻界 |
| 完成 | “欢迎回来，{昵称}。刚才的事情已经替你接上了。” | 查看已完成的注册意图 |

错误文案先说明事实，再说明仍然安全的信息和下一步动作；不责怪用户，不用卖萌掩盖故障，也不只显示技术错误码。

## 邮件

- 显示名称：“小雾 · 幻界”。
- 主题：“验证你的幻界账号”。
- 主按钮：“确认并进入幻界”。
- 包含二十四小时有效期、纯文本链接、非本人操作说明和真实支持渠道。

## 视觉方向

选定方向：[小雾账号注册视觉参考](./account-registration-xiaowu-direction.png)。

小雾是具有少年感的透明非人形界灵，以短簇状雾发、利落眼神和活泼表情表达性格，不使用人类身体或实体服装。注册界面采用纵向旅程线、暗色幻界背景、青紫光门和单步标准表单控件。

视觉参考中的生成式小字仅用于构图，不是产品文案来源；实际界面必须使用本文确认的年龄、密码、隐私与安全规则。

## 声音、动效与无障碍

- 默认使用文字、表情和轻动效；沿用静音设置，语音由用户主动开启。
- 邮箱和密码等敏感内容永远不朗读。
- 支持减少动态效果；所有步骤保持键盘、读屏和清晰焦点状态可用。
- 正文以 14–16px 为基准，按钮和输入框满足手机触控尺寸。

## 数据边界

- 跨设备向导记忆仅包含昵称、明确选择的阅读偏好和引导完成状态，均可查看和清除。
- 不保存注册对话全文、密码或推断出的心理画像。
- 注册分析只记录邀请、开始、失败类型、邮件发送、账号激活和注册意图恢复等非个人化事件。
- 不记录邮箱、昵称、密码、完整错误文本或对话内容；拒绝可选分析后不发送分析事件。

## 年龄、条款与权利

- 账号注册要求访客明确确认已满十四周岁，不收集出生日期。
- 未满十四周岁的访客仍可阅读公开内容，但在监护人同意与儿童个人信息能力建立前不能创建账号。
- 注册前分别确认当前版本的服务条款和隐私政策，并记录版本与时间。
- 生产开放前必须确定真实运营主体、联系邮箱和账号信息请求渠道。
- 查询、更正、导出和删除属于 `AccountLifecycle` 的独立功能；开放注册前至少提供真实可响应的请求渠道。

## 交付边界

账号注册、邮箱确认与注册恢复组成一个可独立验收的功能。登录和密码恢复沿用同一视觉与人格规范，但应分别作为后续功能交付；账号信息请求与自助删除也使用独立 Issue 和 PR。

实现前必须建立 GitHub Issue，明确 actor、成功结果、拒绝条件和失败恢复；随后从最新远端 `main` 创建独立分支，并按 `AccountLifecycle` 正式 interface 的 TDD 顺序交付。

## 生产开放门槛

- 确定真实运营主体与联系邮箱。
- 发布隐私政策、服务条款及账号信息请求渠道。
- 配置并验证生产 Turnstile site key/secret、应用 origin、邮件发件身份和邮件服务 secret。
- 在固定 Preview Worker 和独立 Preview D1 中完成成功、拒绝、越权和失败恢复验收。R2 可以作为平台 Preview 环境的独立 binding 存在，但不是本功能依赖。
- 发布来源已推送 GitHub，工作区干净，本地提交与目标远端完全一致。
