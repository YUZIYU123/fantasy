# 我的书架产品方案

## 状态

已于 2026-08-14 确认共同理解。本文是书架功能的决策完整产品规格；实现必须等待账号注册 PR #35 合并，再从最新远端 `main` 创建独立功能分支。

## 问题与目标

状态正常的账号使用者需要主动保存感兴趣的小说，并快速找到正在阅读或已有更新的内容。当前首页只有被错误称为“幻界书架”的公共作品目录，注册流程虽然保留了加入书架意图，平台却没有私人书架记录、规则所有者、API 或页面。

本功能提供跨设备持久的“我的书架”，并结合公开发布事实和阅读事实给出可靠状态。书架不是阅读历史：开始阅读、产生进度或读完小说都不会自动加入。

## Cloudflare 资源与 adapter

资源选择在实现 interface 前固定。`BookshelfLifecycle` 的外部 interface 只接受领域 command、query、actor context 和普通配置，并返回领域结果；不得暴露 `cloudflare:workers`、D1、Drizzle、R2、Worker `env` 或原始 `Request` 类型。所有 binding 只在 Worker composition root 读取，再通过明确 adapter 接入 module implementation。

| 资源 | 使用 | seam 与 adapter | 职责与理由 |
|---|---|---|---|
| Worker | 是 | `/bookshelf` 页面和书架 HTTP route 是外部 interface 的 HTTP adapter；scheduled handler 是清理 command 的定时 adapter | 托管动态页面、解析请求、取得 actor 与来源上下文、执行 same-origin 校验、映射响应；定时清理过期操作回执和频控记录 |
| D1 | 是 | module 内部 `BookshelfStore` interface；生产 `DrizzleD1BookshelfStore` adapter；受控领域测试使用 in-memory adapter，平台与并发测试使用真实本地 D1 adapter | 保存书架条目、操作回执、频控记录、章节完成证明和待续位置；用唯一约束、条件写入和 transactional batch 保证幂等及原子结果 |
| KV | 否 | 无 seam、无 binding | 私人书架、权限和操作结果需要即时一致；频控阈值等少量配置由 Worker vars 注入，不需要最终一致缓存 |
| R2 | 否，只有平台既有间接读取 | `BookshelfLifecycle` 不接入 R2；React 继续使用当前发布资料中的素材 URL，由既有素材 HTTP adapter 读取 R2 | 书架不上传、复制或删除文件，也不为封面建立第二条 R2 访问路径 |
| Durable Objects | 否 | 无 seam、无 binding | 单账号书架不需要 WebSocket、常驻状态或跨请求内存协调；现有单一 D1 的顺序写入、唯一约束和事务足以实现当前并发语义 |
| Queues | 否 | 无 seam、无 binding | 加入和移出必须返回可查询的同步结果，数据量小且没有异步副作用；过期数据由 scheduled Worker 有界清理 |
| 第三方服务 | 否 | 无 port、无 adapter | 书架不直接发送邮件、处理支付或调用外部认证；登录、注册和会话沿用 `AccountLifecycle` 与 `SessionAuthorization` |
| Worker Observability | 是 | module 内部 `BookshelfTelemetry` interface；生产结构化日志 adapter；测试 spy adapter | 记录不含书架内容和个人信息的结果类别、耗时、频控与恢复状态 |

D1 是当前唯一持久化技术，但故障注入需要独立测试 adapter，因此 `BookshelfStore` 是 module implementation 的内部 seam，不扩大外部 interface。领域测试通过正式 `BookshelfLifecycle` interface 观察结果；SQL 唯一约束、transactional batch、迁移和真实并发另由本地 D1 平台测试覆盖，不能只靠 in-memory adapter 证明。

当前不启用 D1 read replication。所有书架写入和其后的确认读取使用主数据库；若以后启用 read replication，D1 adapter 必须使用 Sessions API bookmark 保证 read-your-own-writes，不能让调用方处理一致性。Cloudflare 官方文档说明 D1 `batch()` 中的语句按顺序执行并作为事务整体回滚，单个 D1 数据库也会逐个处理查询；这些能力足以支撑本规格的短事务，不需要再引入 Durable Objects：

- [D1 Database API：batch 与 Sessions](https://developers.cloudflare.com/d1/worker-api/d1-database/)
- [D1 limits：单数据库并发与吞吐](https://developers.cloudflare.com/d1/platform/limits/)
- [Durable Objects 使用场景](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/)

### 配置注入

Worker composition root 把以下普通值组成 `BookshelfConfig` 后注入 implementation：每页 20 条、账号每分钟 30 次写入、来源地址每分钟 120 次写入、操作结果提示阈值 10 秒、操作回执保留 24 小时。业务规则不得读取 binding 名称或环境变量；local、staging 和 production 显式提供同一配置结构。

## Actor 与能力

- **主要 actor**：具备读者能力的正常账号使用者，包括角色为 `reader`、`author` 或 `admin` 的账号。
- **访客**：可浏览和阅读世界档案，但管理书架时需要登录或注册。
- **待验证或禁用账号**：不能读取或修改书架。
- **管理员能力**：不包含查看或管理其他账号的私人书架。
- **共享创作者凭据**：不是账号，不具备私人书架。

## 产品语言与信息架构

- 公共作品目录的品牌名称统一为“世界档案”，不再使用“幻界书架”“探索书架”或“返回书架”指代公共目录。
- 私人小说集合统一称为“我的书架”，领域术语为“书架”。
- `/` 保持世界档案；新增稳定地址 `/bookshelf`。
- 全局导航提供带文字标签的“世界档案／我的书架”切换。
- 小说详情提供“加入书架”或“已在书架”状态。

领域定义以仓库根 `CONTEXT.md` 为准，包括书架、书架条目、书架生命周期、加入书架、移出书架、书架操作回执、阅读状态、章节完成证明、待续位置、继续阅读和查看小说。

## 正常用户路径

### 登录账号加入小说

1. 账号使用者从世界档案进入当前公开可读的小说详情。
2. 选择“加入书架”。
3. 页面进入待定状态，禁用同一操作按钮但保持焦点稳定。
4. 服务端确认加入后显示“已加入我的书架”；重复加入返回同一成功语义。
5. 账号使用者可以继续停留在详情或进入 `/bookshelf`。

只有当前出现在世界档案中的小说可以新加入，即小说已发布且至少有一个已发布章节。作者或管理员不能借私人书架访问尚未发布的作品。

### 访客加入小说

1. 访客选择“加入书架”时，小雾发出与当前目标有关的登录／注册邀请。
2. 访客拒绝后继续公开浏览；之后再次明确加入时可以重新邀请。
3. 同一设备完成账号激活后，系统自动执行原先明确发起且幂等的加入动作。
4. 小说如果在激活前下线，则不创建条目并明确说明。
5. 在其他设备激活只进入小雾欢迎页，不执行原设备意图。

### 查看我的书架

1. 正常账号进入 `/bookshelf`。
2. 每条显示当前发布的封面、小说名、阅读状态和简短状态提示。
3. 页面每次读取 20 条，以明确的“加载更多”按钮继续分页。
4. 首次加载失败显示错误和重试，不显示假空状态；加载更多失败保留已经加载的条目。
5. 真正为空时由小雾解释书架用途，并提供“去世界档案看看”。

### 查看与继续阅读

- 点击封面或标题始终执行“查看小说”，进入详情和章节目录。
- “阅读中”的主操作为“继续阅读”，恢复最近更新且当前有效的待续位置。
- “有更新”“未开始”“已读”的主操作为“查看小说”，不推测阅读位置。
- “暂不可读”保留基本资料并禁用阅读入口，仍可移出。
- 存在多个待续位置时使用 `updatedAt` 最新且当前有效的位置；下线或版本失效的位置被跳过。
- 没有有效待续位置时进入小说详情，不自动选择章节。

### 移出书架

1. 账号使用者选择“移出书架”。
2. 确认层显示小说名，并明确“阅读进度仍会保留”。
3. 确认成功后条目从书架移除；首版不提供撤销。
4. 重复移出视为成功，不影响章节完成证明或待续位置。

## 阅读状态

状态互斥，并按以下规则推导：

1. **暂不可读**：小说已下线或当前没有已发布章节。
2. **阅读中**：存在有效待续位置，或只完成了当前部分已发布章节。
3. **有更新**：账号曾完成当时全部已发布章节，之后新增了尚未开始的新章节。
4. **已读**：当前所有已发布章节都有章节完成证明。
5. **未开始**：以上均不成立，没有有效阅读事实。

补充规则：

- 开始阅读新增章节后，“有更新”转为“阅读中”。
- 发布新章节可以产生“有更新”；已有章节发布新版本不产生“有更新”。
- 章节完成证明与当前待续位置是可以同时存在的事实。
- 重读已完成章节会创建或更新待续位置，但不会撤销完成证明。
- 重读再次完成后更新完成时间并清除该待续位置。
- 章节新版本使旧待续位置失效，但不撤销完成证明。
- 草稿章节不参与任何状态推导。

## 作品和章节生命周期

| 变化 | 书架行为 |
|---|---|
| 小说下线 | 条目保留并显示“暂不可读”，不能进入阅读 |
| 小说重新上线 | 根据当前章节与阅读事实重新推导状态 |
| 章节下线 | 不再计入当前全部已读；完成证明保留，待续位置暂不可用 |
| 同一版本章节重新上线 | 原待续位置恢复有效 |
| 新版本章节上线 | 旧待续位置失效并从头开始，完成证明保留 |
| 新章节发布 | 已经读完此前全部章节的小说显示“有更新” |
| 发布资料更新 | 书架显示当前发布名称、封面和简介，不显示草稿 |
| 小说记录确实不存在 | 保留条目并显示“作品已不可用”，只允许移出 |

书架条目只保存加入时可见的最小公开快照；正常展示优先读取当前公开资料，小说下线或删除后使用该最后可用公开快照帮助账号使用者识别条目，不能复制或泄露草稿内容。

## 默认排序与分页稳定性

状态组依次为：

1. 阅读中
2. 有更新
3. 未开始
4. 已读
5. 暂不可读

组内排序：

- 阅读中按最近待续时间倒序。
- 有更新按最新未读章节发布时间倒序。
- 未开始、已读和暂不可读按加入时间倒序。
- 时间相同时以稳定书架条目 ID 排序。
- 首次读取由领域模块排序并在 D1 保存一小时有效的分块列表快照；游标只携带快照 UUID 和偏移量，不携带全部条目 ID，也不限制可见条目总数。
- 后续页面按快照顺序批量解析本页条目；翻页期间状态变化不会让当前已加载内容突然跳动，下一次刷新反映新顺序。

## 身份、权限与隐私

- 所有查询和写入从当前会话取得账号，不接受客户端传入 `userId`。
- 账号只能访问自己的书架；其他账号或管理员产品能力不能越权读取。
- 写操作必须通过 same-origin 校验。
- 访客访问 `/bookshelf` 时显示登录／注册入口，而不是空书架。
- 会话过期时要求重新登录，成功后只返回固定的 `/bookshelf`，不接受任意返回 URL。
- 禁用账号撤销会话并拒绝访问；重新启用后恢复原书架。
- 账号信息导出包含书架条目；删除请求执行时永久删除书架条目和操作回执。
- 待验证账号清理同时清除任何异常遗留的书架数据。

## 重复提交、并发与操作回执

- 同一账号与小说由数据库唯一约束保证至多一个书架条目。
- 加入和移出都是幂等领域动作。
- 每次写操作带操作标识；相同标识在同一账号内只能绑定一种动作和一本小说。
- 相同操作标识重复请求只返回原结果，不再次执行。
- 两个设备提交相反动作时，按服务端实际接受顺序串行处理，最后接受的意图生效。
- 已完成旧操作的重放只返回历史结果，不能覆盖之后完成的相反操作。
- 书架操作回执保留 24 小时；过期后先读取真实书架状态，再生成新操作。
- 操作回执不向其他账号泄露结果。
- 页面待定状态只是交互保护，服务端不能依赖前端防重。
- 注册激活自动加入使用由账号和目标小说稳定派生的操作 UUID；结果未知时先用该 UUID 查询回执，不能因验证 token 已消费而丢失恢复路径。
- 小说在提交期间下线等确定性拒绝也写入失败回执，使相同操作标识稳定重放同一公开结果。

## 超时、频控与失败恢复

- 读取请求可以安全自动重试一次，仍失败则显示明确错误和手动重试。
- 加入或移出 10 秒内没有确定结果时显示“结果确认中”，不能宣称成功或失败。
- 结果不确定时先查询操作回执，再使用同一操作标识安全重试。
- 明确失败时恢复到服务端已确认状态，并保留再次操作入口。
- 刷新页面始终从服务端真实状态恢复，不依赖乐观 UI。
- 每个正常账号每分钟最多 30 次书架写入；每个来源地址每分钟最多 120 次。
- 操作结果查询和只读列表不占写入额度。
- 达到频控时不执行写入，并返回准确的重试秒数。
- 阈值由配置注入，领域规则不直接读取环境变量。

故障必须区分：

| 情况 | 结果 |
|---|---|
| 真实空书架 | 展示空状态和世界档案入口 |
| 首次列表读取失败 | 展示错误和重试，不展示空状态 |
| 加载更多失败 | 保留已有条目并允许重试 |
| 无法确认作品公开状态 | 整次读取失败，不猜测“暂不可读” |
| 无法读取阅读事实 | 保留条目和作品资料，显示“暂时无法确认”，隐藏继续阅读 |
| 小说在加入期间下线 | 拒绝新条目并说明已不可加入 |
| 列表读取后小说下线 | 阅读入口即时复核并拒绝进入 |
| D1 明确失败 | 不显示成功，恢复已确认状态 |
| 写入结果未知 | 查询回执后再决定是否重试 |

## 离线行为

首版不支持离线加入、移出或完整书架，也不排队离线写入。断网时保留当前已经显示的内容并标明可能过期；恢复联网后重新读取。浏览器缓存不得覆盖服务端真实状态。

## 数据边界与可观测性

书架条目只保存稳定 ID、账号、小说、加入时间，以及用于下线/删除后识别作品的最小公开名称、封面和简介快照；不保存草稿或派生阅读状态。

操作回执只保存操作标识的安全摘要、动作、公开结果和时间，不记录邮箱、昵称、请求正文或完整错误。结构化日志使用账号与小说标识的不可逆摘要，只记录结果类别和耗时，不记录私人书架内容列表。

首版不生成推荐画像、收藏热榜或面向运营的个人书架查询。

## 数据迁移

- 所有既有账号的书架初始为空，不根据阅读进度自动加入小说。
- 现有已完成进度迁移为章节完成证明。
- 现有未完成进度迁移为待续位置。
- 过去已被重读覆盖而丢失的完成事实无法可靠恢复，不猜测补写。
- 迁移同步更新 `db/schema.ts`，由 `pnpm db:generate` 生成并检查迁移产物。
- 迁移必须处理异常孤儿进度，不能为不存在的账号或章节创建可访问事实。

## 深模块边界

`BookshelfLifecycle` 是书架规则的唯一所有者，统一负责：

- 加入资格和私人归属。
- 幂等加入、确认移出和操作回执。
- 阅读状态与排序推导。
- 继续阅读目标选择。
- 分页、频控、并发顺序和失败恢复。
- 账号禁用、信息删除及异常孤儿数据的书架语义。

它读取 `CreationLifecycle` 拥有的公开发布事实和 `ReadingSession` 拥有的阅读事实，但不接管创作状态转换、章节推进或媒体时序。`AccountLifecycle` 只拥有账号安全状态；`SessionAuthorization` 提供即时 actor 与权限。HTTP route 只解析请求、获取 actor、调用正式 interface 并映射响应；React 只渲染状态、发送事件和回送 effect 结果。

Cloudflare 资源 adapter 全部属于 implementation 内部 seam：

- Worker HTTP adapter 将已解析的 actor、领域目标、操作标识和不含原始地址的来源指纹交给 module。
- D1 adapter 隐藏 Drizzle query、SQL、transactional batch、唯一约束、分页 cursor 和迁移细节。
- scheduled Worker adapter 只调用清理领域 command，不直接删除 D1 行。
- telemetry adapter 只接收白名单结果事件，不接受书架内容、邮箱、昵称或完整错误。
- React 不直接访问 D1、KV、R2、Durable Objects、Queues 或第三方 SDK。

该边界记录于 ADR-0012。

## 手机体验与无障碍

- 读者端继续以手机视口为唯一设计基准，桌面保持居中手机布局。
- 世界档案与我的书架切换入口具有文本标签，不只使用图标。
- 阅读状态不只靠颜色表达。
- 加载、成功、失败和结果确认中通过可读状态区域通知读屏。
- 确认层打开时焦点进入，取消或完成后焦点回到触发按钮。
- 键盘可完成加入、查看、继续、加载更多、移出和重试。
- 封面使用已发布替代文本；下线条目不能泄露未发布替代文本。
- 操作待定时禁用按钮，但不移走焦点或让页面突然跳动。
- 尊重减少动态效果设置。

## 明确不做

- 收藏单个章节。
- 因阅读、产生进度或读完而自动加入。
- 文件夹、标签、手动分类、手动阅读状态或自定义排序。
- 评分、笔记、短评、公开分享或查看他人书架。
- 更新通知、邮件提醒或推送。
- 基于书架的推荐、排行或运营画像。
- 批量加入、批量移出或导入外部书单。
- 阅读历史替代品。
- 离线写入队列。
- 对书架数量设置可见上限。

## 验收范围

### 成功路径

- 正常账号加入、查看、继续、确认移出。
- `reader`、`author`、`admin` 均能使用自己的书架。
- 同设备账号激活自动完成此前书架意图。
- 稳定分页、排序和刷新后恢复。

### 拒绝与越权

- 访客、待验证账号和禁用账号。
- 加入下线或没有已发布章节的小说。
- 跨账号读取或修改。
- 管理员试图读取其他账号书架。
- same-origin 校验失败和写入频控。
- 其他设备激活试图执行原设备意图。

### 幂等、并发与恢复

- 重复加入、重复移出和相同操作标识重放。
- 两个设备提交相反操作。
- 加入与小说下线并发。
- 读取失败、写入明确失败和 10 秒结果未知。
- 操作回执查询、同标识重试和刷新恢复。

### 状态与生命周期

- 未开始、阅读中、有更新、已读和暂不可读。
- 多个待续位置及最近有效位置选择。
- 小说或章节下线、重新上线、新章节和新版本。
- 重读保留完成证明并产生独立待续位置。
- 发布资料更新与草稿内容隔离。

### 数据与账号

- 历史完成与待续数据迁移。
- 既有账号保持空书架，不自动导入。
- 账号禁用、重新启用、信息导出和删除。
- 异常孤儿数据清理。

### 体验与工程门槛

- 手机视口、键盘、读屏、焦点、减少动态效果和稳定分页。
- 先通过正式 `BookshelfLifecycle` interface 编写失败测试，再实现模块，最后连接 HTTP 与 React adapter。
- 至少覆盖成功、拒绝、越权和失败恢复路径。
- 运行迁移生成检查、`pnpm lint`、`pnpm test` 和 Standards／Spec 双轨 code review。
- 资源 seam 测试覆盖 D1 production adapter、受控 test adapter、scheduled Worker adapter 和 telemetry spy adapter；不得让正式 module 测试绕过外部 interface。
- 使用独立 Preview D1/R2 验收后才可合并。

## 依赖与交付边界

- 阻塞依赖：账号注册 PR #35。该 PR 提供受限注册意图及同设备激活接续能力。
- 本功能使用一个独立 Issue、功能分支和 PR，不与账号注册、Preview 基础设施或无关修复混合。
- 实现分支只能在 #35 合并后，从最新远端 `main` 创建。
- 书架不得绕过现有“生产注册必须具备真实责任主体和权利渠道”的门槛；已有正常账号仍可使用。
